## Product outcome and boundaries

The next increment makes the existing native-text PDF → Markdown → lexical retrieval → current-conversation answer/draft workflow recoverable and convenient. Users can repeat PDF addition without losing notes, see what needs attention, resume an exported model task, select papers for both Q&A and writing, and receive a Markdown file whose citations still match current source bytes. Skills handle the internal JSON; ordinary users need not compose it.

This is the lightweight `video_paper_wiki_research` surface. Keep `vpwiki`, canonical Vault/operator flows, 67 catalog/overlay entries, schemas and locked dependencies unchanged. No OCR, Docling execution, model/API client, embedding database, external service, UI server, real Vault operation, Git mutation or merge is part of a Builder packet. Current-model writing happens in the active conversation, outside Python runtime. Structural citation validation does not certify factual correctness.

## Shared API and error convention

Modules live under `src/video_paper_wiki_research/`. New APIs take `pathlib.Path` roots, return JSON-serializable dictionaries with `ok: bool`, `status: str`, `message: str`, and may raise the existing `ResearchError` for invalid arguments or unsafe paths. CLI must turn expected errors into JSON with nonzero exit; no traceback, `ok=true` failure, or output-file creation on rejection. Existing error names retain their meaning. Expected closed outcomes are returned as `ok=false`; tests must assert both status and absence/preservation of output.

New status names: `LIGHT_CONTEXT_INVALID`, `LIGHT_SELECTION_INVALID`, `LIGHT_OUTPUT_CONFLICT`, `LIGHT_SESSION_INVALID`, `LIGHT_SESSION_CONFLICT`, `LIGHT_WORKSPACE_BUSY`, `LIGHT_PAPER_CONFLICT`. Missing or changed index/source generation is `INDEX_STALE`; malformed source anchors/metadata remain `SOURCE_INVALID`; unsafe workspace paths remain `WORKSPACE_INVALID`. T1 inspection uses diagnostic rows instead of raising for individual damaged entries.

No shared-file concurrent writers: T1 owns `light_pdf.py`/`light_workspace.py`; T2 owns `light_index.py`/`light_context.py`; T3 owns `light_workflow.py` and three Skills; T4 alone owns CLI/docs. T2 preserves existing private functions used by T1 (`_paper_dirs`, `_load_paper`, `_load_index`, `_index_is_current`) and their return shapes. New orchestration is one-way: workflow → PDF/index/context/workspace; context → index/qa/writing; workspace → index; PDF must not import workflow/context/workspace. Pure `light_qa.py` and `light_writing.py` stay unchanged.

## A. PDF publication, reuse and workspace inspection — T1

Keep `extract_pdf(pdf_path, workspace_root, *, title=None)` and all existing success fields. Add `disposition: created|reused|recovered`. PDF identity is the lowercase SHA-256 already used by `papers/<digest>`.

For a new paper, publish `source.md` and `source.json` together by staging a complete two-file directory on the same filesystem and atomically renaming it to the absent paper directory. Never expose a final paper directory with only one output. Preserve existing metadata schema, true page anchors and Unicode half-open slices. Do not copy the PDF or retain extracted temporary duplicates after success.

Use a per-paper OS advisory lock in `workspace/.light-transactions/` to serialize cooperating adds and recover after process death; lock acquisition is bounded/nonblocking and an active owner returns `LIGHT_WORKSPACE_BUSY`. It must work on both macOS and Linux. Persistent lock files must not themselves imply an active process. Staging ownership state stays outside the directory published to `papers/`. The exact internal transaction filenames are T1 implementation details, but the marker must bind schema, PDF digest and owned relative paths. A retry may recover/remove only recognized generated artifacts whose ownership and exact allowed entry set are validated. Unknown extras, symlinks or ambiguous partial final directories are preserved and refused, never recursively cleaned. No PID-only lock or age-based deletion. T1 may expose internal injection seams for tests, not user fault-injection flags.

A complete existing paper with matching identity and structurally valid anchors is reused, preserving both files byte-for-byte, even when a user edited Markdown and index metadata is stale. Same PDF from another path is the same paper; keep the existing source path/title. If an explicit nonblank `title` conflicts with existing metadata title, return `LIGHT_PAPER_CONFLICT`; do not overwrite it. On reuse, return current page count and metadata warnings. A missing source pair, unsafe paths or invalid anchors cannot be silently repaired by destructive re-extraction. T1 validates the source identity instead of relying on `_load_paper`'s legacy fallback. Process-crash recovery is required; power-loss durability and arbitrary hostile concurrent filesystem replacement are not claimed.

New `light_workspace.inspect_workspace(workspace_root) -> dict` is strictly read-only, including missing directories. Return `schema=video-paper-wiki.light-workspace.v1`, resolved `workspace_root`, `state=empty|ready|needs_index|needs_attention`, `index_state=missing|current|stale|invalid`, `index_id` (string or null), `papers`, `diagnostics`, `next_actions`. `papers` are sorted by paper_id and contain paper_id, title, page_count, markdown_path, markdown_sha256, metadata_stale, warnings; no full text. Invalid/suspicious entries appear in diagnostics with relative path, code and message, not silently omitted. Report abandoned/active transactions without modifying them. State precedence: unsafe/damaged entries or pending transactions → needs_attention; no papers/no damage → empty; valid papers with noncurrent index → needs_index; otherwise ready. Expected missing index is not damage. `ok` is true when inspection itself completes; the state describes readiness.

## B. Selection and live evidence validation — T2

Add `light_context.export_context(workspace_root, *, kind, query, requirements="", paper_ids=None) -> dict`, where kind is exactly `qa|writing`. It calls lexical search and the existing pure exporter, binds resolved `workspace_root`, and adds `selected_paper_ids`: normalized explicit selection, or `[]` for all. Keep existing light-context.v1 fields, including the existing `paper_ids` meaning. Default top_k remains 8. No hidden index rebuild in this API.

`paper_ids=None` or `[]` means all papers. A nonempty selection must contain only strings of exact form `sha256:<64 lowercase hex>`; normalize duplicates in first-seen order without silently dropping blanks or malformed IDs. Every selected ID must exist in the current workspace, otherwise `LIGHT_SELECTION_INVALID` with empty evidence; never broaden to all papers. Filter before top-k. No matches in a valid selection is `NO_RESULTS`. Q&A and writing must share these rules. Existing `light_index.search` signature stays; strengthen it accordingly and preserve deterministic ranking.

Add `light_context.validate_live_context(workspace_root, context) -> dict`. A success returns `ok=true,status=OK,index_id,workspace_root`; no writes. Validate light-context.v1 schema, successful context state, kind, index_id, selection syntax/subset and all evidence shapes. Legacy contexts without `selected_paper_ids` remain supported; that omission does not bypass evidence checks. `workspace_root`, when present, must equal the explicit resolved root, otherwise existing `LIGHT_WORKSPACE_MISMATCH`.

Read the live current sources and index; recompute source slices/chunk identities and compare canonical stored index records with those derived from source, including paper metadata, chunk set, text, offsets, page, title, hashes and lexical statistics. A tampered stored index is not an authority. Reject malformed/duplicate/missing/extra chunks or changed df/token counts. Guard malformed types without leaking KeyError/TypeError. All supplied evidence rows, including unused rows, must exactly match one actual current derived chunk for every identity/text field. Score only needs the existing finite-number rule; it is not an identity field. Selection is an additional restriction. A stale source/index/missing paper or context index_id different from current is `INDEX_STALE`; a forged evidence row against a current valid index is `LIGHT_CONTEXT_INVALID`. A no-op rebuild with identical source snapshot remains valid: index_id is content identity, not a timestamp. Rebuilding after actual source edits must invalidate old context.

Add read-only `light_context.render_document(workspace_root, context, document, *, output) -> dict` and writing `light_context.import_document(workspace_root, context, document, *, output, overwrite=True) -> dict`. Render validates live context, invokes the existing pure kind-appropriate renderer, converts links relative to the actual output parent, and returns the prospective bytes as `markdown` plus `citations`, resolved `path` and `output_sha256` (SHA-256 of UTF-8 Markdown). It does not create output parents or files. Import uses render and validates live context again immediately before installing the output. Markdown links with spaces/parentheses must work as in the accepted quickstart. Move/reuse the necessary link transformation logic in this module; do not import CLI. T4 switches old CLI paths to import_document; T3 uses render_document to bind its completion intent.

Stage output bytes in a unique same-directory file; install atomically. Reject symlink/nonregular output targets and unsafe parent traversal. Output must not alias workspace paper sources, index, transaction/session state or other managed inputs. `overwrite=True` preserves ordinary import's successful replacement behavior; any validation/I/O failure leaves existing output intact. `overwrite=False` is atomic create-only, returns `LIGHT_OUTPUT_CONFLICT` if any target already exists, and never overwrites even identical content (T3 owns idempotency). Clean up only owned temporary files. Check before parent creation where possible; failure must not create the requested Markdown. Revalidation bounds observed races; do not claim locking of unrelated external editors.

## C. Resumable current-model workflow and Skill — T3

Add `light_workflow.prepare_workflow(workspace_root, *, kind, query, requirements="", paper_ids=None, pdf_paths=None) -> dict`, `workflow_status(workspace_root, *, session_id=None) -> dict`, and `complete_workflow(workspace_root, session_id, document, *, output) -> dict`.

Prepare may add an explicit list of local PDFs through T1 and build/rebuild the local lexical index through T2 before export. Consume pdf_paths in input order; repeated files/digests are permitted and use T1 reuse. It may create a missing workspace only when pdf_paths is nonempty; otherwise missing workspace returns WORKSPACE_INVALID without creating it. Existing PDF Markdown is reused. It does not re-extract user edits. Adding several PDFs is incremental, not a batch rollback: if a later one fails, report completed additions and the failure, without pretending to publish a session. Missing/unsafe sources stop affected work. `NO_RESULTS`/`INSUFFICIENT_EVIDENCE` is not a model task: return ok=false with that status, session_id=null, additions/index result/next_actions, and no session directory or usable model context. Repeating prepare for identical request+snapshot returns the same session; source change produces a new session, preserving history. Revalidate live context after export and immediately before session publication; a changed snapshot must not be published as awaiting_model.

Use `workspace/.light-workflow/sessions/<session_id>/` with immutable `request.json`, `context.json`, `manifest.json`; publish the complete directory atomically. Canonical encoding C(x) is UTF-8 JSON with ensure_ascii=False, sort_keys=True, separators=(",", ":"), without trailing LF and with nonfinite numbers forbidden. Every persisted workflow JSON file is exactly B(x)=C(x)+one LF, and its SHA hashes those exact file bytes. Model document SHA hashes C(document), since the API receives an object. Request has exactly schema=`video-paper-wiki.light-workflow-request.v1`, resolved workspace_root, kind, nonblank query, string requirements, and normalized selected_paper_ids. PDF additions are reflected by the context index identity, not an unrelated run timestamp.

`session_id` is lowercase SHA-256 of C({schema:"video-paper-wiki.light-workflow-identity.v1",request_sha256,context_sha256}). Manifest is fully derived and has exactly schema=`video-paper-wiki.light-workflow-manifest.v1`, session_id, workspace_root, index_id, request_sha256 and context_sha256. Compare its whole expected B(manifest) bytes, request/context fields and identity; no extra manifest fields. Validate name, hashes, regular files and allowed entry set on every use. Never trust a recomputed self-reported hash without checking session identity. Do not mutate frozen request/context to refresh it.

Prepare success contains ok=true,status=OK, `schema=video-paper-wiki.light-workflow.v1`, `session_id`, `state=awaiting_model|complete|stale|needs_attention`, `context_path`, `request_path`, `manifest_path`, `context` (the actual exported document), `next_actions`, and `reused` boolean. Return `awaiting_model` for a new usable task. The context is the only evidence input for the current model. Successful complete returns ok=true,status=OK,state=complete plus session_id, path, output_sha256 and reused; expected failures retain their closed status and ok=false. A status inspection which completes returns ok=true,status=OK even when the inspected state is stale/needs_attention. Invalid API arguments/unsafe roots fail normally. This separates command execution from inspected readiness.

Completion validates the session and live context, then writes output via T2 create-only import. Make output installation plus completion recording retryable across process interruption: persist a validated immutable completion intent before output installation, binding canonical document SHA, absolute output path and expected rendered output SHA; a retry can accept an already installed file only if it exactly matches this validated intent and the same model document/output. An existing file without matching prior intent is a conflict, even if bytes happen to match. Then publish immutable `completion.json` binding schema, session_id, request/context/manifest/index identity, document/output hashes and output path. Use a per-session OS lock to serialize cooperating completions; do not rewrite old receipts or resume by overwriting user content. T3 computes prospective bytes using T2 render_document; no guessed private T2 symbol dependency. Alternative internal design satisfying these exact recovery/identity outcomes is allowed.

Intent filename is `completion-intent.json`, schema=`video-paper-wiki.light-workflow-intent.v1`; required exact fields are schema, session_id, context_sha256, document_sha256, output_path and output_sha256. Receipt schema=`video-paper-wiki.light-workflow-completion.v1`; exact fields are schema, session_id, request_sha256, context_sha256, manifest_sha256, index_id, intent_sha256, document_sha256, output_path, output_sha256. Both use B encoding. Verify all cross-bindings, not only individual hashes. The model document must be an object; QA uses text, writing uses markdown with existing text fallback, and existing pure-renderer duplicate/unknown-field behavior is preserved. Relative output resolves against cwd. Always call import_document with overwrite=False.

Allowed stable session entries are the three prepared files; optionally completion-intent.json; optionally completion.json only when intent is also present. Output is external to the session and is represented by receipt, not a copied result file. Session locks and staging go outside stable session directories. Recognized staged work under `.light-workflow/staging/` must have a versioned ownership marker binding the session and exact owned names; only these proven owned temporary artifacts may be recovered under the session lock. Unknown entries/symlinks are preserved/refused. Read-only status reports recognized abandoned staging and unknown entries as diagnostics. Never create completion intent/receipt on model-validation failure; an already persisted intent may remain on a later I/O/revalidation failure and must be reported as unfinished, not complete.

Status is read-only and validates persisted bytes plus live context. No session_id lists concise session_id-sorted rows plus workspace inspection; one id returns detail. A missing workspace returns an empty list and missing-workspace diagnostic without creating it; an existing empty workspace returns an empty list without that diagnostic. A nonexistent explicit session_id returns LIGHT_SESSION_INVALID. State precedence: damaged manifest/intent/receipt, changed or missing completed output → needs_attention; otherwise live context invalid/stale → stale; valid completion/output → complete; otherwise valid unfinished context → awaiting_model. Completed historical output is preserved even if source changes; stale status explains re-prepare. A valid unfinished intent with missing or matching output remains awaiting_model with next_actions to retry complete using the same document and output; expose expected document/output hashes, not invented success. A mismatching intent output is needs_attention. Exact same completion may be reused only after revalidating live context and matching intent/receipt/output/model bytes. Divergent output/model is `LIGHT_SESSION_CONFLICT`; malformed state causes completion to fail `LIGHT_SESSION_INVALID`, while status reports needs_attention. Refuse traversal session IDs and symlink state; no cleanup of unknown files.

Add these commands (no network/admin delegation):

```text
workspace inspect --workspace PATH

workflow status --workspace PATH [--session-id HEX64]
```

Repeatable flags use one value per occurrence. `--document JSON` means a UTF-8 JSON file path, not inline JSON; CLI reads it into the model-document object. All successful workflow payloads remain the backend dictionaries; CLI adds no second persistence layer. Expected errors produce actionable JSON and nonzero status. `status`/`inspect` are read-only.
