# SOURCE conversion — concrete successor draft

This is a review draft, not an implementation freeze. Baseline will be the exact
accepted SOURCE-PUBLICATION delivery. Root owns local implementation and existing
assistants review it. Preserve all legacy schemas, the 67 seed/overlay entries,
zero-egress execution, no committed PDF and no real Vault/operator action.

## Intended workflow

An explicit current lightweight knowledge record is converted into provisional
canonical claims with exact Markdown citation spans, using its already captured
and registered source. The result is the existing source-publication prepared
request. The existing inspect command remains the only transaction authority
handoff. No model output is treated as human assessment or display choice.

The research entrypoint takes workspace_root, light paper_id, record_id, capture
authority path, explicit paper metadata path, batch_id, operation_id, vault_root
and a supplied UTC proposal timestamp. The record must be the current validated
lightweight head for that paper, with current source bytes and citation chunks.
New-paper metadata must supply a real published_at value; do not substitute the
conversion date or guess authors/taxonomy. Existing metadata is preserved unless
explicitly supplied and permitted by the source publication contract.

Retain source.md/source.json, authority/metadata input files, and the complete
bounded .light-knowledge tree before reading through existing record/head/job
validators. Keep all named directory edges, complete sets and file bytes through
assembly and preparation on success and failure. Re-derive source observation
with formal_source._observe and chunks with the existing deterministic chunker.
Require exact equality to the capture observation and registered raw bytes.
Filesystem or stale-light failures cannot return a prepared result.

Collect current canonical state under one retained audited Vault snapshot. Find
the earliest actual source-registration receipt, load its exact historical ledger
snapshot and create/reuse the association with associate_source. If the current
ledger itself has that exact required hash, it can supply the absent snapshot;
a later different ledger is not a substitute. Missing history is a named refusal.
Preserve all old observations, associations, decisions and events byte-for-byte.

## Claims and compilation

Map summary -> one_sentence_conclusion; method -> method; architecture ->
representation_architecture; training_data -> training_data; experiments ->
experiments_results; limitations -> limitations; code_resources -> code_resources;
open_questions -> research_question. Unknown sections produce no invented claim.
Only summary is a core candidate; every new claim remains provisional. Free-text
lightweight concepts are reported as unmapped suggestions; taxonomy uses only
explicit pinned axis/slug references.

For each provisional section, canonical claim text is its exact supplied text.
Each cited current chunk becomes a Markdown locator over the exact registered
source, association, Unicode charspan, page anchor and excerpt SHA-256. Validate
resolution against actual bytes. Reject normalization collisions or one claim
that would be assigned incompatible section ownership; do not alter historical
text to hide a collision.

New IDs get a system v2 genesis event. Existing IDs retain exact text/ref/owner.
Changed evidence creates a v2 system evidence_invalidation successor and returns
the claim to provisional with reviewed_at null. An unchanged fingerprint keeps
its prior assessment and event bytes. No automatic human review, source review
promotion, display selection or reactivation of retired claims. Preserve other
claims/refs, including material absent from this lightweight record.

Build complete paper/code/concept compiler input from current state plus explicit
new claims/association. Preserve legacy event bytes and use their actual hashes
in assessment-heads. Recompute both registries and all compiler pages; update
source page links explicitly. Let source publication preserve old ledger snapshots
and validate the complete prospective graph before staging. Use the existing
receipt/transaction helper; do not implement another receipt constructor.

Idempotent conversion with unchanged current record/evidence/metadata returns the
existing no_change envelope. Only meaningful row/record changes advance supplied
metadata timestamps. The prepared request must bind the same current basis used
for assembly; retain and verify assembly inputs through that check.
