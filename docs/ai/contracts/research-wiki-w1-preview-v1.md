# research-wiki-w1-preview-v1

Revision 1 · 2026-09-06 · Architect review candidate (not frozen until the packet records exact hash and both reviews).

## 1. Scope and evidence

Implement the complete offline W1 flow: canonical arXiv request → connector observation → version-bound metadata → abstract-only Chinese preview → append-only user decision; list pending/ingest/skip/later previews. Networking and model inference remain in the repository Skill's platform tools/current conversation. The Python package neither fetches nor calls a model. W2 consumes immutable references; W1 never downloads PDFs, ingests, publishes, mutates a Vault/index, or closes a human gate.

Inputs: R3.3 PRD body SHA-256 `b9eeef61bce1532fd039dd82660637abebf02d9bdba2f9819681685a1a5896c8`; R3.2 Fable convergence and FABLE-015; R2 W0 freeze as historical architecture. These documents are unchanged. FABLE-002/008 stay with the user and do not affect this interface.

`CAP-WEB-OBS-001` ran before this contract: samples SHA-256 `68518fe631e9e7163d97d8a2c5ed7326e8eec620148a665be42857b517db395a`, in `artifacts/verification/RESEARCH-WIKI-W1-PREVIEW/CAP-WEB-OBS-001/observation-samples.json`. Two separate `web.run open` calls exposed normalized official abs pages and version markers/history. No raw HTTP bytes, status, complete headers, redirect chain, origin wire length or DNS/IP were exposed. Tool-reported content type is not a raw header. Samples retain bounded metadata excerpts with omissions explicitly stated; they are not complete abstract fixtures or user selections.

Architect decision: freeze **`arxiv-abs-normalized-v1`** as W1's implemented adapter. Do not call it Atom. The common observation interface describes both profiles, but byte-exact execution/parsing is unavailable in W1 and is refused explicitly; a later executor/Atom packet must supply its own capability observation, receipt, hardening and tests. This is the R3.3 page-adapter branch, superseding R2's assumption that the legacy API is always usable. Adding unused XML code would not prove a missing connector capability. If Atom is introduced later, it must use the locked environment/stdlib, reject DTD/entities/XInclude and bound depth/elements/fields.

## 2. Package, ownership and storage

- Add `src/video_paper_wiki_research/` to the existing wheel and expose `vpwiki-research = video_paper_wiki_research.cli:main`; same distribution/version, no new dependencies or lock changes. Keep `vpwiki` command tree and engine schemas unchanged.
- Reuse engine integer-only JCS, error envelope and safe staging/read helpers through a thin research wrapper. No copied upstream implementation, admin imports, network clients, subprocess invocation, model SDK, SQLite/index mutation or second canonical store.
- Generated durable objects live only under `.work/research/<session>/{requests,observations,metadata,proposals,decisions}/`. Session is 1–64 ASCII letters/digits/underscore/hyphen, starts alphanumeric. No user-chosen output paths. All object files are JCS UTF-8 plus exactly one LF; request/observation/metadata/preview filenames are `<content_sha256>.json`, decision filenames are a six-digit sequence plus `.json`.
- Source inputs may be bounded local regular files. Reject symlinks, special files, traversal and invalid UTF-8/duplicate JSON keys/non-finite numbers. Read generated references only from their expected kind/session location; verify canonical bytes, ID and both hashes, not filenames alone. Enforce 1 MiB per input/object; nested JSON depth ≤32. No file outside this boundary is written.
- Every CLI command is one local writer. Independent immutable objects may be staged sequentially; never claim they form an atomic transaction. A command retains and checks the named research/session directory identities across its writes/reads and on all exits; persistent replacement is `WORK_PATH_UNSAFE`. A partial failure can leave valid immutable orphan objects, never a success receipt or decision for a missing graph. Success and list/cache reuse revalidate the entire referenced graph. Reuse established descriptor-based staging, and keep any needed wrapper local to research. No modification of engine staging semantics.
- Identical files are idempotent; conflicting existing bytes are refused, never overwritten. Max 256 files in each kind directory and max 256 decisions/session; exceeded/unsafe unexpected entries fail explicitly. Research artifacts (especially decisions) are retained until explicit user deletion/export policy in a later packet; no automatic pruning or advertised backup coverage in W1.

## 3. Schema family and identity

Seven new JSON Schema resources under research-owned `src/video_paper_wiki_research/schemas/`: `common.v1.schema.json`, `connector-request.v1.schema.json`, `connector-observation.v1.schema.json`, `arxiv-metadata.v1.schema.json`, `paper-preview.v1.schema.json`, `preview-decision.v1.schema.json`, `skill-contract.v1.schema.json`. Six are closed document schemas; common is reusable `$defs`, not a durable object. Five data objects include request plus the four required core objects. Each has independent kind/schema version and lifecycle; decision is never a preview variant. No engine schema is extended. Reuse common identity/reference/time/unknown/budget definitions and the existing envelope/JCS implementation; this modest separate-resource count prevents authority/retention semantics leaking between kinds.

All data documents use exactly `{schema_version, kind, id, content_sha256, data}`. `schema_version` is the schema stem including `.v1`; `kind` is one of `request|observation|metadata|preview|decision`, fixed per schema. Let `body = {schema_version,kind,data}`. `content_sha256 = SHA256(JCS(body))`; `id = rw1:<kind>:<content_sha256>`. A reference is exactly `{id,sha256}` where `sha256 = SHA256(JCS(complete_document) + LF)`. Thus an exact artifact/file hash is distinct from its nonrecursive content hash. References always bind the exact serialized object, including envelope identity. Changing any field, model identity, time, prompt or choice changes identity. CLI seals IDs itself; sealed input documents are revalidated. No floats, extra fields or cross-kind fields are accepted.

Times use UTC RFC3339 `YYYY-MM-DDTHH:MM:SSZ`; versions are integers 1–9999 or null only where specified. Hashes are lowercase 64-hex. IDs/refs must match kind and recomputed bytes. Shared unknown identity is `{value,identity_source,reason}`: `identity_source=platform_reported|self_reported|unknown`; unknown requires literal `value="unknown"` and nonempty reason; known requires nonempty value other than `unknown`, with reason null. A self-report is visibly unverified, never promoted to platform identity. Model and runtime use independent identity objects. Empty strings and contradictory unknown combinations fail.

## 4. Request and local budgets

Request `data` has exactly: `entity_id`, `requested_version`, `resolution_policy`, `source_url`, `method`, `adapter`, `budget`. `entity_id` is canonical unversioned arXiv ID. `resolution_policy=explicit|latest_observation` agrees with nullable requested_version. Method is GET, adapter is `arxiv-abs-normalized-v1`, source URL is generated as `https://arxiv.org/abs/<canonical-id>[vN]`.

Accept bare modern ID (`YYMM.NNNN` or `YYMM.NNNNN`, valid month), legacy category ID (`category/YYMMNNN`, permitted category characters letters/digits/dot/hyphen, valid month), optional lowercase vN, optional `arXiv:` prefix, or an exact HTTPS arxiv.org `/abs/` URL. Do not guess from titles. Reject userinfo, any port, query/fragment, trailing extra path, percent-encoded ambiguity, mixed/suffix host, HTTP, control characters, whitespace within the ID, zero/oversized version and malformed date digits. Surrounding whitespace may be stripped; canonical output has no such whitespace. Implement locally with stdlib; do not use `identity.establish_canonical_paper_id` to mutate or redefine canonical engine identity.

Budget fixed fields: `max_requests=1`, `deadline_seconds=20`, `max_normalized_bytes=1048576`, `max_transport_bytes=1048576`, `min_interval_seconds=3`, `max_redirects=2`. These are requested policies, not proof of transport enforcement. The Skill uses one open on the generated URL, serializes arXiv requests with at least 3 seconds between starts, no hidden retry/search/PDF fallback. No API-global rate-limit guarantee is claimed across other sessions. A failure or unobservable deadline is recorded; no tight retry loop. Normalized return byte length is checked locally; time may be observed after return but the tool lacks a cancellation timeout argument. Headers/redirect/wire limits remain unverified without executor evidence.

Request identity excludes wall-clock creation time, so identical policies/input produce the same request. Per-session cache lookup on `paper request` selects the newest fully valid matching metadata graph no older than 24 hours, with observed_at not in the future (caller supplies `--now` for deterministic replay; default UTC clock). Tie-break by artifact hash. Cache keys separate explicit vN and unversioned policy and retain resolved version. Expired or `--refresh` reports fetch required; it never fetches itself. Cache reuse returns exact original references/timestamps/capability, not a fabricated new observation. Corrupt existing graph is refused rather than silently treated as a cache miss.

## 5. Observation and page adapter

Observation `data` has exactly: `request`, `observed_at`, `executor`, `source_url`, `capability_profile`, `reported_content_type`, `transport`, `outcome`, `payload`. Executor uses the identity object above. Source URL must equal the generated request URL; it is a caller-recorded connector observation, not independent proof that a supplied file came from the internet. Record fixture/live context in separate verification evidence; hashes authenticate bytes, not the truth of an executor claim.

`transport` contains exactly `final_url`, `redirect_chain`, `headers`, `content_type`, `dns_ips`, `raw_response_sha256`, `wire_bytes`, `timeout_enforced`, `redirect_policy_verified`. Each is `{value,unavailable_reason}`. Null requires nonempty reason; observable non-null values require null reason and proper type. In normalized W1 raw_response_sha256 must be null. Tool-reported type is `reported_content_type` and cannot be silently copied into origin headers. Claimed URLs must remain HTTPS exact arxiv.org (no userinfo/port/query/fragment); claimed redirects ≤2 all same origin; over-budget wire_bytes is refused even though absence is allowed. Normalized use never certifies absent transport checks.

`outcome` is exactly `{status,retry_after_seconds}`: status `ok|not_found|timeout|rate_limited|failure`; retry_after_seconds is null or nonnegative integer ≤86400. Failures can be stored as observations but never generate metadata/preview. `ok` requires text payload and a complete usable page; failure payload may be null. Errors map to stable codes in §9.

Normalized payload is exactly `{format,text,sha256}`, format `arxiv-abs-normalized-text-v1`, sha256 over raw UTF-8 text bytes supplied by connector bridge, length ≤1 MiB. Text is the normalized connector result, not HTML or Atom and not a hand-invented metadata JSON. Implement an explicit parser for the observed arXiv abs rendering: optional tool/source header and `L<number>:` prefixes, citation decoration removed without changing linked label text, title/Authors/Abstract/Subjects/Cite-as/Submission-history boundaries. Extract values from named sections only; never scan an unrelated link or footer as the paper identity. Ambiguous, duplicate conflicting, missing or truncated required sections fail closed. Preserve author order and abstract paragraph order. The supported rendering/adapter version is narrow; new renderer formats require fixtures and a revision, not guessing.

Page identity/version must be established from this-version cite marker or an equivalent explicit same-page version marker tied to the paper ID. Submission history is supplementary: complete history boundaries permit yes/no for other versions; incomplete history can prove yes from another entry but cannot prove no/latest. A current version and complete visible history permit `latest_at_observation = (resolved_version == max(history_versions))`; otherwise null. A separately observed explicit latest marker may prove true only if it refers to this paper/version. Reject any conflict between trusted named markers. Never infer v1 merely because only one version string was found.

The byte-exact branch is closed and distinct: payload `{format:"raw-response-reference-v1",path,sha256,bytes,executor_receipt_sha256}`; final_url/redirect_chain/content_type/raw_response_sha256 must be non-null and hash-consistent. The path is a future confined relative research reference, never opened in W1. `paper observe` refuses this profile with `CONNECTOR_CAPABILITY_UNAVAILABLE` before any raw parsing. No schema-valid byte-exact object is a claim that W1 has a byte-exact executor or can ingest it.

## 6. Metadata and explicit version refusals

Metadata `data` has exactly: `request`, `observation`, `entity_id`, `requested_version`, `resolved_version`, `latest_at_observation`, `other_versions_exist`, `observed_at`, `title`, `authors`, `published_at`, `updated_at`, `categories`, `abstract`, `abstract_url`, `pdf_url`, `adapter`, `preview_only`, `ingest_authorized`. `latest_at_observation` is boolean or null; other_versions_exist is yes/no/unknown. The resolved version is always known and positive for successful metadata. Both dates are UTC times derived from same-page history for initial/current version; unavailable required bibliographic data refuses metadata rather than fabricating dates. Titles 1–2048 chars, authors 1–100 entries of 1–256 chars, categories 1–32 entries of 1–128 chars, abstract 1–32768 chars. No empty/whitespace-only strings. Canonical abs/PDF URLs always include resolved vN; `preview_only=true`, `ingest_authorized=false`.

Metadata is deterministically derived and validated against its exact request/observation; a caller cannot replace metadata.abstract, dates or version and merely reseal its own hash. Successful explicit request requires resolved=requested and same-version abstract. Stable errors: `ARXIV_VERSION_MISMATCH` for another served version/conflicting markers; `ARXIV_VERSION_UNAVAILABLE` for explicit-version not_found; `ARXIV_VERSION_UNCONFIRMED` where response cannot establish requested/current version. Missing abstract/bibliography is `ARXIV_METADATA_INCOMPLETE`. Entity mismatch is `ARXIV_ID_MISMATCH`. No silent fallback, search or second request.

Unversioned requests may produce metadata for a proven version with latest_at_observation null. UI then displays `latest_unknown`, observed time and resolved version; no assertion that it is current. Metadata, all version flags and time are copied into preview and verified against it. W1 does not change engine paper identity or support multi-version ingestion.

## 7. Preview and model provenance

Ship one versioned UTF-8 prompt template with the package. `paper preview context` returns the exact task prompt formed as template bytes + one LF + canonical complete metadata bytes, its SHA-256, metadata ref and expected proposal shape. This hash represents this task input, not all invisible platform/system prompts. Skill gives this task input to the current model; it never claims CLI inference or a second provider call.

Unsealed proposal is exactly `{generator,generated_at,prompt_sha256,sections}`. Generator is exactly `{model,runtime}` using the identity objects (§3); unknown is a first-class valid branch. Sections is a closed object with keys `one_sentence`, `research_question`, `method`, `contributions_results`, `limitations`, `relevance`. Each is exactly `{text,classification}`, text 1–4000 characters; classification `extracted|inferred|ambiguous|unknown`. Six sections form the Chinese preview. Facts absent from the abstract must not be labeled extracted; uncertainty must be visible. Deterministic checks do not prove semantic entailment or language quality; S reviews these separately.

`preview validate` verifies the linked metadata graph, recomputed task-prompt hash, proposal limits and identity fields, then seals preview with data exactly `{metadata,entity_id,requested_version,resolved_version,latest_at_observation,other_versions_exist,observed_at,evidence_scope,generator,generated_at,prompt_sha256,sections,preview_only,ingest_authorized}`. Scope is literal `abstract-only`, preview_only true, ingest_authorized false. All fields enter content and exact file hashes. `preview render` is read-only and returns Markdown in the JSON success envelope: title/explicit version/observed time/latest label, all six labeled sections and uncertainty classifications, source link, abstract-only limitation, actual generator identity/source and available actions. Do not display unsupported transport/model claims or imply full-paper review.

## 8. Decision, list and W2 handoff

Decision `data` is exactly `{preview,sequence,previous,action,selected_version,user_record}`. Sequence is integer 1–256 and previous is null for first event, else exact prior decision ref. Action is ingest/skip/later. selected_version must equal the preview resolved version for ingest; null for skip/later. Ingest requires explicit CLI `--selected-version N`, even for an unversioned input; latest_unknown must be shown to the user before choosing this known version. No selection is synthesized from silence or a fixture.

`user_record` is exactly `{event_id,text,recorded_at,source}`: event_id is a session-unique safe slug 1–64, text 1–4096 chars, recorded_at UTC, source user_message/fixture. This is a recorded user message (or labeled fixture), not authentication, an approval-ref, signing proof or permission to execute admin actions. The Skill supplies actual user text and never claims fixture choices are real. User controls when to record an action.

Decisions are one session-wide immutable sequence. CLI accepts caller event_id for idempotent replay, reads/validates full contiguous chain, and stages the next sequence with create-only semantics. Exact same event+payload returns existing event; reusing event_id with changed preview/action/version/text is DECISION_CONFLICT. Gaps, divergent predecessors, identity mismatches or conflicting same sequence refuse. No mutable head file. Competing writers cannot overwrite a choice; they receive a conflict and must re-read. List derives the last event per preview by sequence (not timestamp), defaults to pending, and preserves older decisions. Ingest output includes exact decision, preview, metadata and observation refs and selected version as a **W2 reference handoff**, not a newly authoritative request/schema or actual ingestion. W2 later resolves/checks these before plan/acquisition.

## 9. CLI surface and errors

All commands run from checkout root. Reuse `{ok,command,data}` / `{ok:false,command,error:{code,message,details}}` envelope and exit 0 success / 2 refusal / 75 staged conflict. `--help` may print conventional usage. No arbitrary execute/config/raw HTTP commands.

```text
vpwiki-research paper request --arxiv INPUT --session SESSION [--now UTC] [--refresh]
vpwiki-research paper observe --session SESSION --request REQUEST.json --observation INPUT.json
vpwiki-research paper preview context --session SESSION --metadata METADATA.json
vpwiki-research paper preview validate --session SESSION --metadata METADATA.json --proposal PROPOSAL.json
vpwiki-research paper preview render --session SESSION --preview PREVIEW.json
vpwiki-research paper decide --session SESSION --preview PREVIEW.json --action ingest|skip|later --event-id ID --user-text TEXT --source user_message|fixture [--selected-version N] [--recorded-at UTC]
vpwiki-research paper list --session SESSION
```

Observe input is an unsealed observation data object; CLI validates/seals/stores it, then derives/stores metadata or returns failure with stored observation ref. Request is a generated sealed file. All generated input references must belong to the declared session. Full-input limits run before parsing and before writes; errors never echo unlimited input. Preview proposal is the unsealed shape (§7), not an additional durable schema. Optional deterministic clock arguments are caller-supplied timestamps, never falsely described as platform observation.

Codes: `ARXIV_ID_INVALID`, `CONNECTOR_REQUEST_INVALID`, `CONNECTOR_CAPABILITY_UNAVAILABLE`, `OBSERVATION_MISSING`, `OBSERVATION_BINDING_MISMATCH`, `OBSERVATION_PROFILE_INSUFFICIENT`, `RESPONSE_TOO_LARGE`, `MEDIA_TYPE_REFUSED`, `ARXIV_ENTRY_NOT_FOUND`, `ARXIV_ID_MISMATCH`, `ARXIV_VERSION_MISMATCH`, `ARXIV_VERSION_UNAVAILABLE`, `ARXIV_VERSION_UNCONFIRMED`, `ARXIV_METADATA_INCOMPLETE`, `CONNECTOR_TIMEOUT`, `CONNECTOR_RATE_LIMITED`, `CONNECTOR_FAILURE`, `PREVIEW_PROPOSAL_INVALID`, `PREVIEW_SCOPE_INVALID`, `DECISION_INVALID`, `DECISION_CONFLICT`, `ARTIFACT_INVALID`, `ARTIFACT_BINDING_MISMATCH`, `SESSION_LIMIT_EXCEEDED`, plus existing staging boundary codes. Missing/invalid options use `USAGE_ERROR`. Failure order: validate local shape/budgets → binding/profile/outcome → entity/version → metadata completeness → proposal/decision. Named-directory safety checks dominate any error if persistent replacement is detected. For unversioned not_found use ARXIV_ENTRY_NOT_FOUND; explicit not_found uses ARXIV_VERSION_UNAVAILABLE. A provided non-HTML tool media report is MEDIA_TYPE_REFUSED; absent report is allowed with transport reason. No XML-invalid code is advertised by the page-only implementation.

The latter validates with the research-owned closed skill-contract schema: exact fields `schema_version`, `skill_name`, `skill_revision`, `skill_md_sha256`, `intents`, `commands`, `input_schemas`, `output_schemas`, `allowed_tools`, `network_policy`, `write_policy`, `budget`, `retry_policy`, `idempotency`, `stable_errors`. Freeze skill_revision=1, skill_name=video-paper-preview, schema_version=skill-contract.v1; remaining fields are bounded arrays/closed objects or strings describing this contract. Commands list the seven concrete CLI forms above, never an admin command. Runtime budget is one connector request/20 seconds requested/1 MiB normalized bytes/3 seconds between starts, no automatic retry. Allowed tools are local CLI, current model and platform read-only Web open; only that platform layer has network access. Manifest is lintable documentation, not capability enforcement. Hash binds exact SKILL.md bytes. Skill automatic discovery remains enabled; no new global settings.

It cannot bypass failures with curl, direct PDF download, guessed version or invented provenance. A model/runtime unknown example and local fixture walkthrough are required.
