## Checked requirements and compatibility

Required exact lists/dicts retain missing/null/false/empty distinctions. All active and retired bindings participate without lifecycle inference. The future catalog can join the original validated events; an ordered-event result or mutable registry is unnecessary. Empty/empty has an exact result, while either nonempty side must meet coverage.

2. **Complete graph — sufficient, independently implementable.** Draft lines 134-149 require one genesis, no duplicate ID, complete claim coverage, same-claim predecessors, no fork/cycle, one terminal and full traversal coverage, with iterative traversal. This closes the old `_validate_events` gap: `contracts.py:1267-1278` traverses backward from a visible terminal without comparing its visited set to all supplied events. A per-claim adjacency/index pass and iterative traversal can enforce the new rules in linear graph work; there is no need to sort by event IDs or timestamps. Lines 227-233 correctly distinguish synthetic graph-cycle testing from practically unavailable self-consistent content-addressed cyclic event fixtures.

3. **Historical fingerprint transitions — consistent with plan, not old prospective behavior.** Draft lines 151-166 correctly distinguish parent/child edge policy from head/current binding. Human transitions preserve parent fingerprint and change state; invalidation changes fingerprint and goes provisional; only terminal fingerprint matches current evidence. Returning to a prior fingerprint is allowed when the immediate parent differs. The old `contracts.py:1183-1195` current-FP-for-every-event loop cannot be reused. The new rules match `projection-input-v1.md:143-179` and active plan section 5.4 without silently changing old prospective admission. Required system/human shape remains supplied by `assessment-event.v1.schema.json:24-54`.

4. **Raw text and claim identity — now explicit and compatible.** Draft lines 117-122 preserve the difference between `identity.claim_id` (`identity.py:436-453`, normalized text) and `identity.sha256_hex` (`:576-577`, raw UTF-8). Requiring raw text equality through every event hash, while not requiring normalized spelling at API input, avoids silently changing old golden identities or rehashing immutable events. Same normalized claim material with a different raw spelling is not a new hash algorithm; it simply cannot match old raw-text event hashes. Draft line 16's identity-text rationale is qualified correctly by lines 119-122.

5. **UTC fractional precision — compatible closed profile.** Draft lines 76-83 state full Gregorian bounds, seconds 00..59, optional 1-9 fractional digits and literal uppercase T/Z. This is compatible with the event schema's common `utc_timestamp` format plus pattern (`common.v1.schema.json:110-114`) and deliberately avoids runtime's narrower seconds-only `_TIMESTAMP`. Fractional spelling must remain unchanged for `identity.event_id` (`identity.py:509-519`); valid equal or decreasing times are allowed because graph edges order events. Date projection is first ten validated characters, so Python datetime microsecond precision need not truncate or reserialize 7-9 fractional digits. Reusing the existing event schema still requires new strict fullmatch/calendar checks around its older pattern behavior.

6. **65,536-byte limits and aggregate budget — coherent and bounded.** Draft lines 55, 65-66 and 87-100 define the additional claim-text cap and the already-frozen locator wire cap separately from the whole virtual-tree runtime budget. `projection_runtime._preflight` (`:52-128`) already charges exact-type trees, aliases per occurrence, the virtual root/keys, encoded scalar/ratio material, depth, occurrences and integer magnitude. Reuse it before shape/normalization/hash work and map non-resource errors to SCHEMA_INVALID. Then enforce text character count before UTF-8 encoding and byte length before claim normalization/hash. Text-cap excess is a resource excess under lines 183-186 and therefore PROJECTION_LIMIT_EXCEEDED, not a claim identity failure. `ledger_locator.encode_ledger_evidence` (`:190-202`) revalidates complete flat evidence and routes through `_encode_validated` (`:91-104`) for the exact full wire cap. This includes the prefix/envelope overhead; it is not a cap on flat evidence JSON bytes. No duplicate aggregate charging needs to be accumulated across independent codec calls.

8. **Collision precedence and error taxonomy — sufficient to implement.** Draft lines 108-115 explicitly put all claim-shape checks before duplicate-material comparison, then duplicate comparison before individual stated claim-ID mismatch. This new-profile distinction does not alter old duplicate-ref behavior in `tests/contract/test_prospective_validation.py`. Other unrelated multi-error priority is intentionally not promised (lines 207-209), so no additional global sort or validation-phase framework is required. Shape-valid event ID mismatch can precede a later graph failure, as the synthetic-cycle testing section explicitly permits.

9. **Pointers, safe errors and isolation — feasible with a local wrapper.** The error families named at lines 188-199 exist or are the exact frozen codec strings (`LEDGER_LOCATOR_INVALID`, `LEDGER_EVIDENCE_INVALID`, `PROJECTION_LIMIT_EXCEEDED`). ## Implementation cautions already resolved by the draft

- Force `expected_schema="video-paper-wiki.assessment-event.v1"`; never infer or default it from arbitrary event input as the old prospective helper does.
- The event schema's human same-state allowance is intentionally narrowed only by the new whole-history profile. Keep old schema, event golden and prospective tests unchanged.
- Recompute event ID from the full original event except `event_id`, without normalized timestamps/reason/text fields and without runtime comparison hashes.
- Validate every claim shape before collision detection. Do not let a duplicate with invalid evidence bypass full codec admission simply because its stated ID already appeared.
- Do not infer deprecated from retired lifecycle, infer scientific assessment from evidence counts, or treat actor labels as authenticated human authorization.
- Do not expose omitted-event detection as authenticated completeness: rollback, event filenames/bytes, source/artifact closure, transaction separation and core replacement co-publication remain explicitly outside this API.
- No old prospective helper return/copy semantics must be changed. New output consists only of a fresh dict and strings, so there is no need to copy or retain input evidence/events.
