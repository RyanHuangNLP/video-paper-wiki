## Findings by requested boundary

1. **Whole-wire canonical form is complete.** Draft lines 42-56 and 110-126 define the exact prefix, closed envelope, no duplicate keys, no envelope floats/exponent spelling, integer-only JCS and exact whole-wire re-encoding. This rejects reordered keys/alternate escapes/whitespace/-0 even when a generic JSON parser would accept their semantic values. String-valued whitespace is preserved. Existing `jcs.py` UTF-16 key ordering and UTF-8 output can be reused without broadening its numeric domain. Decode must not simply parse and return a normalized locator.

2. **Rational numeric domain is executable without approximation.** Lines 58-73 specify sign, gcd reduction, power-of-two denominator, 2048-bit bounds and exact binary64 ratio round-trip. For d=1 returning int intentionally also handles a maximum-finite float represented as an integer ratio; the resulting integer remains below 2048 bits. For d>1, computing n/d and comparing its finite `as_integer_ratio()` to the original pair distinguishes true representability from rounding. `OverflowError` during division is a locator refusal, not an uncaught numeric exception. The smallest subnormal `[1,2**1074]` fits the bound; `[1,2**1075]` is representationally invalid, not an integer-budget violation. `[1,2**2048]` violates the integer budget first. No bbox geometry constraints beyond common are silently introduced.

3. **Common and identity compatibility is explicit.** `common.v1` `$defs.pdf_locator/code_locator` supplies required/optional shapes. The draft adds strict built-in scalar types, lines and charspan ordering, source safe-ID subset and fullmatch semantics as a new local profile; it does not alter existing schema/identity entrypoints. PDF artifact paths already use the common derived-path grammar. Repository casing is retained in wire although existing evidence identity casefolds it; that is not a conflict because wire preserves the complete locator while identity intentionally selects normalized identity fields. `identity.py:_PDF_FIELDS/_CODE_FIELDS` excludes bbox/charspan and code symbol; preserving those in wire does not change old fingerprints.

4. **Optional fields and flat evidence are unambiguous.** Only PDF bbox is moved to bbox_rationals. Optional charspan/symbol retain presence and exact values; null is invalid, not absence. Domain evidence is flat, so encoding removes only relation before validating a complete locator. Wire evidence has exactly three keys. Relation conversion supports->supports, contradicts->contradicts, uncertain->context is local to validated tagged evidence, never a global rewrite of upstream context. Copies must not retain aliases; no in-place popping/removal from caller objects.

5. **Resource order is compatible with frozen runtime guards.** Lines 102-118 and 160-166 permit reusing `_preflight` and `parse_projection_json`. Domain/evidence preflight occurs before deepcopy or schema recursion; wire type and character count precede UTF-8 allocation, followed by scalar UTF-8 validation and full byte count <=65536 including the prefix. The parser already supplies allocation-before-count/depth and bounded decimal-int conversion defenses. The codec must translate non-resource runtime parser/value errors rather than leak `PROJECTION_JSON_INVALID` or `PROJECTION_VALUE_INVALID`; resource refusals retain their code. Valid UTF-8 scalar text means equality of reconstructed str and original wire also establishes exact UTF-8 byte equality.

6. **Error layers and pointers can be implemented from the draft.** Outer shape/relation/source-ID failures in decode-evidence use `LEDGER_EVIDENCE_INVALID`; malformed locator material uses `LEDGER_LOCATOR_INVALID`; resource failures retain `PROJECTION_LIMIT_EXCEEDED`. Encode-evidence checks relation after whole-input preflight, then locator fields, so missing/unknown locator fields remain locator errors. Domain source_id is a locator field; wire outer source_id is separately an outer field. Decode locator field diagnostics need envelope-relative `/locator/...`; ratio diagnostics use `/bbox_rationals/...`. Encode locator diagnostics are domain-relative. Forwarded errors retain these logical pointers, not a fabricated byte offset into the outer wire string. Raw spelling/prefix/canonical re-encoding errors use `""`. Exact keyword-specific choice for a missing field is not frozen and need not be invented as a new error protocol.
