# manual-pdf-extraction-v1

Revision 1 · 2026-09-06 · review candidate; implementation starts only after exact packet freeze.

## 1. Purpose and boundaries

This is the first implementation of the user's simplified first version: manually supplied PDF → located knowledge proposals → existing publication/retrieval → simple current-model drafting. It replaces online W1 as the critical-path first packet. This packet implements safe intake, parser-profile preflight, an optional offline authoritative parser producer, and source-context/proposal validation. Subsequent packets provide consolidated publication/status, Q&A and simple writing. A four-file exporter alone is not completion of the knowledge product.

Baseline is `bcff631ce12fe777ab6db7a4dd6531db3bbaea3f`; scope input is `docs/ai/video-paper-wiki-manual-pdf-v1-addendum.md` SHA-256 `9c86d50772d0993d0fdfa1a56f4b3a0934693f1e4fe6e87e97703a40f1eed646`. Preserve both PRDs, CAP samples and the unfrozen online-W1 draft. No networking, arXiv request/metadata/version logic, extra default dependencies, canonical engine lifecycle/schema changes, admin execution, real Vault mutations or human-gate decisions.

Two implementation owners are distinguished: research code in the default distribution does safe local intake and deterministic context/proposal work; optional `operator/parser_executor/` code performs model preflight and real Docling conversion in an externally prepared environment. It is a separate package/entrypoint, never imported or called by the agent CLI. Default CI uses injected converter fixtures and never installs Docling/models or invokes vpwiki-admin. Real conversion is a separately recorded external lane. A model fixture is not a scientific or provenance result.

## 2. Reuse and package surfaces

Add `src/video_paper_wiki_research/` to the existing wheel and `vpwiki-research` console entrypoint without altering default dependencies/uv.lock or existing vpwiki commands. Reuse public JCS, identity, strict read helpers, existing PDF validation semantics (64 MiB, 300 pages, reject encryption/invalid PDF), stage_bytes, run/plan/draft schemas and PDF locator wire encoder. An internal helper may be imported from the pinned same-repository implementation when no public equivalent exists; document each such call and do not change its semantics. No source copying from external projects.

New default-package resources: `manual-pdf-intake.v1.schema.json`, `parser-profile.v1.schema.json`, `source-analysis-context.v1.schema.json`, `source-analysis-proposal.v1.schema.json`, and `common.v1.schema.json` under research-owned schemas; one `paper-analysis-v1.md` task prompt. Four new durable/transport schemas plus one reusable defs resource. Reuse existing ingest-plan, approval-ref, run-manifest, Docling artifact-set, paper-analysis-draft and locator schemas unchanged. Config/model files use the closed forms specified below and are embedded as exact objects in the profile, rather than receiving separate schema families. All refs resolve locally; schema validation never fetches a URI.

Every new document is exactly `{schema,id,content_sha256,data}`. Schema names are `video-paper-wiki-research.<stem>.v1`; kind-specific ID is `mp1-<intake|profile|context|proposal>-<64hex>`. Compute content_sha256 over engine JCS of `{schema,data}`; ID uses that hash. Save complete document as JCS + one LF. Exact references are `{id,sha256}` over complete saved bytes, never content_sha256. All unknown keys, duplicate keys, non-finite numbers, floats in these envelopes, invalid UTF-8, ambiguous types and mismatched hashes fail. Raw Docling export is a distinct float-capable JSON artifact and is not labeled integer JCS. New JSON inputs/objects are at most 8 MiB and depth 32, max string 262144 UTF-8 bytes unless a smaller field limit is specified; source/model/document files use their explicit separate limits. Proposals transport draft locators as described in §5 to keep float geometry out of integer envelopes.

Use UTC `YYYY-MM-DDTHH:MM:SSZ`; safe batch/session IDs reuse existing batch grammar. All generated research files are confined to `.work/research/<session>/manual-pdf/`; content-addressed PDF input goes through existing staging to `.work/blobs/<sha256>` (the explicit manual-intake exception to research's own-state layout). This local copy is authorized by the supplied-file task, not an approval-ref. No configurable destination or alternate blob root for this command. Never edit/delete the original file or inbox.

Within manual-pdf, intake/context/proposal envelope files live in `intakes|contexts|proposals/<content_sha256>.json`; proposal legacy draft and Markdown are `<content_sha256>.draft.json` and `<content_sha256>.md` in proposals. Profile has the three fixed filenames defined in §4 (`profile.json` for its envelope), runs use run-id, artifact-set descriptors use exact file hash, and failure records use `failed-runs/<run-id>.json`. These are exact create-only layouts, not a second mutable registry. References resolve only inside this layout/session. No unbounded scans: at most 256 intake/context/proposal/artifact-set/run records per family; overflow is refused explicitly.

Each write is immutable and idempotent for identical bytes. A retained descriptor wrapper verifies named checkout/.work/research/session/output roots across compound operations, including failure exits. Use stage_bytes for installations. Exact existing bytes reuse; different bytes at a fixed path conflict; symlink/FIFO/device/directory/file-type substitutions or persistent named-directory replacement fail. A failed compound operation may retain immutable partial staging, but cannot return completion. Revalidate referenced graph before success/resume. Do not represent sequential installations as an atomic Vault transaction.

## 3. Safe intake and plan handoff

`vpwiki-research pdf intake --pdf PATH --session ID [--paper-id CANONICAL_ID]` reads a bounded regular non-symlink PDF with stable identity/bytes, checks PDF magic, unencrypted 1–300 pages and ≤67108864 bytes, hashes exact bytes, stages the blob and an immutable intake document. Check source again on all exits; changed bytes or identity is SOURCE_CHANGED. Do not extract arbitrary paper metadata to invent DOI/arXiv/version/license. Explicit paper ID is normalized/validated through existing identity; absent means `sha256:<digest>`. An existing different binding is never silently merged or upgraded.

Intake data is exactly `{paper_id,pdf_sha256,size_bytes,page_count,media_type,blob_path,original_name,provided_identity}`: media_type application/pdf; blob_path `.work/blobs/<sha>`; original_name is a bounded basename only (no host path); provided_identity is null or the user's normalized ID. No time/approval fields, so identical input and explicit facts are idempotent. Result includes intake ref/path and `next_action=awaiting_parser_profile`. This is staged input, not receipt-backed capture.

`vpwiki-research pdf plan --intake INTAKE --profile PROFILE --batch-id BATCH` revalidates intake/blob/profile, creates the existing paper-source/local-blob request with stable_subject_id `paper:<paper_id>`, parser fields from exact profile hashes, fixed max_bytes=67108864/max_pages=300/max_requests=1 and `network_targets=[]`, then calls the existing plan builder/stager. The legacy schema's min max_requests=1 is an allowance, not evidence of a request; no network occurs. No optional arxiv_id/pdf_url is synthesized. Return exact existing plan path/hash, intake/profile refs and `next_action=awaiting_external_approval_ref`. It must never create an approval-ref. Subsequent prepare/capture-inspect/operator apply remain the existing commands; README/ingest Skill can guide them without changing authority.

## 4. Profile preflight and optional parser

Provide separate `operator/parser_executor/pyproject.toml` and package `video_paper_wiki_parser_executor`, console `vpwiki-parser`. This package depends on this engine plus exact Docling 2.117.0/core 2.92.0 in its optional execution environment. It is not added to the root wheel/default lock and cannot dispatch vpwiki-admin. Production CLI never exposes a fake backend switch. Tests may inject a fixture converter via Python API only.

`vpwiki-parser profile --artifacts-path MODELS --session ID` reads an explicitly supplied local model tree, emits parser-config.json, model-manifest.json and sealed profile in `.work/research/<session>/manual-pdf/profile/`. No PDF run or model download. The tree must be a real directory; all entries regular files/directories, no symlink/special/hard-linked files or unsafe portable paths. Bound depth 16, ≤4096 files, per-file ≤4 GiB and aggregate ≤32 GiB. Hash files streaming with stable descriptor/stat checks; inventory sorted by relative UTF-8 path. Recheck complete tree membership/named identities and file content hashes before returning; adding/removing/changing a model fails, not a new profile under the same command. Empty tree is PARSER_MODELS_MISSING. This records actual supplied files; it does not certify they are the correct model set until conversion succeeds.

Parser config is exactly `{schema,engine,engine_version,core_version,options}`; schema `manual-pdf-parser-config.v1`, engine docling, versions pinned above; options exactly `{enable_remote_services:false,allow_external_plugins:false,do_ocr:false,do_table_structure:true,generate_page_images:false,generate_picture_images:false,do_code_enrichment:false,do_formula_enrichment:false,do_picture_classification:false,do_picture_description:false,do_chart_extraction:false,document_timeout:300,accelerator_device:"cpu",num_threads:4}`. CPU/4 threads is explicitly selected via the pinned AcceleratorOptions API. This is the initial digital-PDF profile, not an OCR guarantee. Local model path is runtime input and is not a semantic config/hash field. No options are silently inherited for remote/enrichment behavior. Unsupported pinned-runtime option/API is PARSER_RUNTIME_INCOMPATIBLE. Pinned API references: [converter](https://raw.githubusercontent.com/docling-project/docling/v2.117.0/docling/document_converter.py), [pipeline options](https://raw.githubusercontent.com/docling-project/docling/v2.117.0/docling/datamodel/pipeline_options.py); read-only API inspection is not a real runtime/model test.

Model manifest is exactly `{schema,files,total_bytes}`, schema `manual-pdf-model-manifest.v1`; files is sorted unique `{path,sha256,size_bytes}` for every regular file under supplied model root. Config and model JSON use engine JCS + LF. Profile data is exactly `{parser,parser_config,model_manifest}` where parser is the existing five-field Docling plan profile with config/model exact SHA-256, and parser_config/model_manifest are the exact closed objects just described. Fingerprint is derived from parser via existing identity API and returned, not an independently selectable value. Runtime versions are checked before profile creation using importlib.metadata; unavailable runtime is PARSER_RUNTIME_MISSING. No self-reported version substituted for installed metadata.

`vpwiki-parser export --vault-root VAULT --captured-pdf CAPTURED --profile PROFILE --artifacts-path MODELS --session ID --run-id ID` is authoritative only for an existing receipt-backed `.raw/captured/<sha>.pdf`. Read through existing retained Vault snapshot/audit rules; source must be in ever_claimed_raw, exact filename/hash and valid PDF. Retain/revalidate source and profile/model bytes throughout run and on failure; do not accept a similarly hashed unrelated path as authority. Source capture/receipt must already exist. Conversion receives retained exact PDF bytes through a local DocumentStream/BytesIO (not a URL or a mutable source filename), with recorded config and explicit local artifacts_path.

Force HF_HUB_OFFLINE, TRANSFORMERS_OFFLINE and telemetry-off in the dedicated process; disable remote services/external plugins and prevent Python INET socket creation/DNS/connect in this execution path. Restore patched process state on exit where API is used in tests. Offline flags alone are not claimed as OS sandbox proof; default agent runtime never imports this producer. No subprocess/network download fallback. Docling conversion must report SUCCESS, valid document export with at least one nonempty text item and page provenance consistent with the PDF, and preserve all exported text/table/picture/formula metadata. Empty/scanned-without-usable-text or partial conversion refuses with explicit capability/parse error; no pypdf output can masquerade as Docling. Full page count is processed within the 300-page/300-second requested parser limit; unsupported OCR/enrichment/picture pixels are clearly reported rather than guaranteed.

Emit exactly existing four roles under `.work/research/<session>/manual-pdf/runs/<run-id>/`: `document.json`, `parser-config.json`, `model-manifest.json`, `run.json`. `document.json` is deterministic stdlib JSON serialization of `document.export_to_dict()` using ensure_ascii=False, sort_keys=True, separators=(',',':'), allow_nan=False, plus LF; finite float coordinates are preserved. No invented Docling structure/version/source metadata. A complete export ≤64 MiB and JSON depth ≤64 is required. Config/model bytes are identical to preflight. `run.json` uses existing `video-paper-wiki.run-manifest.v1`, actual vpwiki/python/Docling/core versions, source/config/model exact input hashes, document exact output hash, actual started_at/ended_at, error_code null and existing pipeline_fingerprint. No receipt hash or plan hash cycle. Success stamps are never created on failure.

An already complete valid run-id directory returns the original exact run after revalidating its source/profile/model/document bindings without rerunning inference; a different input/profile for the run-id is a conflict. Incomplete prior run-id is explicitly incomplete/conflicting and requires a fresh run ID, never overwrite. For failed attempts keep one bounded `failure.json` in a distinct failed-run location with actual code/time/input refs when confinement allows; it is not a valid success run-manifest or canonical artifact. No automatic retry or timestamp rewriting.

Build and validate the unchanged Docling artifact-set descriptor from these four exact roles; save it separately under `manual-pdf/artifact-sets/<SHA256-of-canonical-descriptor>.json`, outside the four-file run directory. Return its path, four paths/hashes/fingerprint and the exact existing `vpwiki ingest package` handoff parameters. Package and publication context remain caller-supplied under existing validation; exporter does not invent operation groups/receipts or auto-apply. Existing ingest package must accept exported bytes with the fixture receipt-backed PDF, and later projection/audit must validate source/run/document bindings. Float-capable document bytes stay exact through packaging.

## 5. Located source context and model proposal

`vpwiki-research pdf context --intake INTAKE --artifact-set SET --document DOCUMENT --run RUN --source-id SOURCE --vault-root VAULT --upstream-root PIN --session ID` consumes the existing validated Docling artifact-set and four-role files (config/model discovered only as exact named siblings to DOCUMENT). Verify set/run/source/PDF/profile hashes, immutable expected artifact paths and source binding from the capture evidence; a caller source_id alone is not authority. The required Vault read verifies receipt/source-ledger binding, and `verify_pinned_source_id` verifies SOURCE against stored captured path/digest in the authenticated pinned helper; no local source-ID formula. This permitted read-only engine helper is the only subprocess route involved. Source must be the captured document source owned by this intake paper; if paper record does not yet exist, require exact capture source binding and treat context as staged/prospective, not published paper ownership. Do not use gold or fabricate source IDs.

Context data is exactly `{intake,artifact_set_path,artifact_set_sha256,local_artifacts,run_sha256,paper_id,source_id,pdf_sha256,document_path,document_sha256,pipeline_fingerprint,evidence_scope,blocks,omitted,prompt_sha256}`. artifact_set_path is the confined descriptor path; local_artifacts is a closed four-kind map to `{path,sha256,size_bytes}` for the retained same-session run files. These local paths permit exact graph replay before derived artifacts are published; document_path is the canonical prospective path and must not be substituted for a missing staged source. Scope `parsed-pdf-text`. Deterministically enumerate Docling `/texts/N` nodes in document order with nonempty text and valid page provenance. Each block is `{block_id,text,locator}`; block_id content-addresses source/document/ref/page/charspan/text bytes. Locator uses existing exact PDF locator, canonical future artifact path, exact document hash, page/ref/text hash and nonempty charspan within the original node text. Use existing locator wire encoding to preserve any float geometry; store locator as that canonical wire string in the integer-JCS context. Never clip a block and keep its original text hash/span. One context accepts ≤128 blocks and ≤262144 UTF-8 text bytes; select in document order, record every omitted eligible node as `{ref,reason}` up to document max nodes 20000. Overlarge omitted inventory fails rather than silently drops provenance. Table bodies/pictures/formulas not representable by this first text-node context remain in the complete export and appear in omitted/capability notes; no claim that all semantic content was understood. This is a basic text context, not a full scientific parser guarantee.

New `locator_truth.py` is a mandatory workflow validator, independent of existing shape-only engine validators. It verifies exact artifact bytes/path/hash and source before resolving a strict canonical RFC 6901 `/texts/N` pointer (no aliases, leading-zero index, group/container or missing node). Node `self_ref`, if present, must agree. Text is used verbatim; charspan is Unicode-code-point half-open `[start,end)`, `0 <= start < end <= len(text)`, and text_sha256 hashes exactly that UTF-8 substring. A locator page must match exactly one provenance item covering that span on the same node and the actual PDF page range. Docling bbox `{l,t,r,b,coord_origin}` must have finite ordered coordinates and a declared `TOPLEFT` or `BOTTOMLEFT` origin; transform BOTTOMLEFT to TOPLEFT using that page's verified height and freeze external locator order `[left,top,right,bottom]`. Require exact finite-number values (canonical rational equality, no tolerance); reject ambiguous provenance/page geometry. Context creation derives page/span/bbox and immediately validates truth. For a node with multiple disjoint valid provenance spans, emit distinct blocks per span in page/span order; overlapping/ambiguous coverage is refused. This workflow does not accept omitted span/bbox as a loophole, even though legacy schemas permit omission. Include adversarial ref/text/span/page/bbox/source/path/hash and origin tests.

Context tasks use shipped prompt bytes + LF + JCS of the context data excluding prompt_sha256. No hidden platform prompt is claimed captured. The prompt asks the current model for existing `paper-analysis-draft.v1` with provisional claims, and gives the closed proposal shape. It does not ask the parser to invent scientific claims. Return the exact task prompt/hash and context reference; CLI never invokes a model or assigns a known model identity without evidence.

`vpwiki-research pdf analyze --context CONTEXT --proposal PROPOSAL --vault-root VAULT --upstream-root PIN --session ID` validates an unsealed `{context,generator,generated_at,prompt_sha256,draft}` proposal. Context is exact ref; generator exactly `{model,runtime}`, each `{value,identity_source,reason}` with platform_reported/self_reported/unknown; unknown requires literal unknown and nonempty reason, known requires nonempty value and reason null. Self-reports remain labeled. Verify complete context graph and prompt hash and recheck source authority/truth. Draft uses unchanged paper-analysis-draft schema, except each incoming locator is supplied as the exact existing canonical locator-wire string from a context block. Decode wires into legacy locator objects only for existing draft validation; the sealed research envelope keeps wires and saves a separate float-capable `paper-analysis-draft.v1.json` for existing review consumers. This is an explicit transport wrapper, not a changed engine schema. Require same paper identity, ≥1 claim and ≥1 locator per claim, every assessment provisional, canonical claim IDs, references only to supplied context blocks/locators, and exact text/page/ref/span/hash identity. Extra or altered locator, invented source/ref or accepted claim fails. Scientific support/language quality is not proven by shape checks; prompt/source context and provisional status remain available for review. No fabricated human assessment event.

Seal proposal in the new proposal schema (same data fields), save immutable JSON plus a deterministic human-readable Markdown preview. It is review input for the existing canonical flow, not a publishable/accepted paper. If no supportable claims exist, return SOURCE_ANALYSIS_EMPTY with the retained context; do not force claims. The first packet's positive fixture must demonstrate nonempty valid provisional claims and true locators, not title-only output. Source changes invalidate context and proposal; never relabel old proposal with a new source hash.
