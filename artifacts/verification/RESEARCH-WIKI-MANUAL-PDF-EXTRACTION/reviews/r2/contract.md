Revision 2 · 2026-09-06 · review candidate; implementation starts only after exact packet freeze.

## 1. Purpose and boundaries

This is the first implementation of the user's simplified first version: manually supplied PDF → located knowledge proposals → publication/retrieval → simple current-model drafting. It replaces online W1 as the critical-path first packet. This packet implements safe intake, parser-profile preflight, an optional offline **staged** parser producer, and prospective source-context/proposal validation. Subsequent packets provide canonical source admission/publication/status, Q&A and simple writing. A four-file exporter alone is not completion of the knowledge product.

Baseline is `bcff631ce12fe777ab6db7a4dd6531db3bbaea3f`; scope input is `docs/ai/video-paper-wiki-manual-pdf-v1-addendum.md` SHA-256 `9c86d50772d0993d0fdfa1a56f4b3a0934693f1e4fe6e87e97703a40f1eed646`. Preserve both PRDs, CAP samples and the unfrozen online-W1 draft. New production paths have no networking, arXiv request/metadata/version logic, extra default dependencies, canonical engine lifecycle/schema changes, admin execution, real Vault mutations or human-gate decisions. Existing isolated operator fixtures in the legacy regression suite remain unchanged; they do not authorize an agent to run admin against real data.

Two implementation owners are distinguished: research code in the default distribution does safe local intake and deterministic context/proposal work; optional `operator/parser_executor/` code performs model preflight and real Docling conversion in an externally prepared environment. It is a separate package/entrypoint, never imported or called by the agent CLI. New focused CI tests use injected converter fixtures, install no Docling/models and never invoke vpwiki-admin. Real conversion is a separately recorded external lane. A model fixture is not a scientific or provenance result.

R1 was rejected at contract hash `fcfc75d40848f9d59771a4f816da3a7d7cdadb55da5dccd40c976c93e81b9d47`: ordinary capture transactions cannot emit a canonical operation receipt/head. Requiring ever_claimed_raw before parsing made the intended new-paper route incomplete, and the first proposal transport mixed locator wires with the legacy object schema. R1 contract/packet are preserved in `artifacts/verification/RESEARCH-WIKI-MANUAL-PDF-EXTRACTION/reviews/r1/`. R2 deliberately separates `staged_extraction` from later `published_extraction`; no existing package/audit/publication check is weakened.

Every new document is exactly `{schema,id,content_sha256,data}`. Schema names are `video-paper-wiki-research.<stem>.v1`; kind-specific ID is `mp1-<intake|profile|context|proposal>-<64hex>`. Compute content_sha256 over engine JCS of `{schema,data}`; ID uses that hash. Save complete document as JCS + one LF. Exact references are `{id,sha256}` over complete saved bytes, never content_sha256. All unknown keys, duplicate keys, non-finite numbers, floats in these envelopes, invalid UTF-8, ambiguous types and mismatched hashes fail. Raw Docling export is a distinct float-capable JSON artifact and is not labeled integer JCS. New JSON inputs/objects are at most 8 MiB and depth 32, max string 262144 UTF-8 bytes unless a smaller field limit is specified; source/model/document files use their explicit separate limits. Proposals transport draft locators as described in §5 to keep float geometry out of integer envelopes.

Use UTC `YYYY-MM-DDTHH:MM:SSZ`; safe batch/session IDs reuse existing batch grammar. All generated research files are confined to `.work/research/<session>/manual-pdf/`; content-addressed PDF input goes through existing staging to `.work/blobs/<sha256>` (the explicit manual-intake exception to research's own-state layout). This local copy is authorized by the supplied-file task, not an approval-ref. No configurable destination or alternate blob root for this command. Never edit/delete the original file or inbox.

Within manual-pdf, intake/context/proposal envelope files live in `intakes|contexts|proposals/<content_sha256>.json`; proposal legacy draft and Markdown are `<content_sha256>.draft.json` and `<content_sha256>.md` in proposals. Profile has the three fixed filenames defined in §4 (`profile.json` for its envelope), runs use run-id, and failure records use `failed-runs/<run-id>.json`. No captured artifact-set descriptor is created in this staged lane. These are exact create-only layouts, not a second mutable registry. References resolve only inside this layout/session. No unbounded scans: at most 256 intake/context/proposal/run/failure records per family; overflow is refused explicitly.

Each write is immutable and idempotent for identical bytes. A retained descriptor wrapper verifies named checkout/.work/research/session/output roots across compound operations, including failure exits. Use stage_bytes for installations. Exact existing bytes reuse; different bytes at a fixed path conflict; symlink/FIFO/device/directory/file-type substitutions or persistent named-directory replacement fail. A failed compound operation may retain immutable partial staging, but cannot return completion. Revalidate referenced graph before success/resume. Do not represent sequential installations as an atomic Vault transaction.

## 3. Safe intake and plan handoff

`vpwiki-research pdf intake --pdf PATH --session ID [--paper-id CANONICAL_ID]` reads a bounded regular non-symlink single-link PDF with stable identity/bytes, checks PDF magic, unencrypted 1–300 pages and ≤67108864 bytes, hashes exact bytes, stages the blob and an immutable intake document. Check source again on all exits; changed bytes or identity is SOURCE_CHANGED. Refuse st_nlink other than 1. Do not extract arbitrary paper metadata to invent DOI/arXiv/version/license. Explicit paper ID is normalized/validated through existing identity; absent means `sha256:<digest>`. Conflicting prior same-session paper↔PDF bindings refuse; no global Vault binding is claimed checked by this local command. Canonical binding is rechecked by the later publication packet.

Intake data is exactly `{paper_id,pdf_sha256,size_bytes,page_count,media_type,blob_path,original_name,provided_identity}`: media_type application/pdf; blob_path `.work/blobs/<sha>`; original_name is the 1–255 UTF-8-byte basename only (no host path/control characters); provided_identity is null or the user's normalized ID. No time/approval fields, so identical input and explicit facts are idempotent. Result includes intake ref/path and `next_action=awaiting_parser_profile`. This is staged input, not receipt-backed capture.

`vpwiki-research pdf plan --intake INTAKE --profile PROFILE --batch-id BATCH` revalidates intake/blob/profile, creates the existing paper-source/local-blob request with stable_subject_id `paper:<paper_id>`, parser fields from exact profile hashes, fixed max_bytes=67108864/max_pages=300/max_requests=1 and `network_targets=[]`, then calls the existing plan builder/stager. The legacy schema's min max_requests=1 is an allowance, not evidence of a request; no network occurs. No optional arxiv_id/pdf_url is synthesized. Return exact existing plan path/hash, intake/profile refs and `next_action=awaiting_external_approval_ref`. It must never create an approval-ref. This optional staging handoff does not execute capture and is not a prerequisite for staged parsing. README/ingest Skill must state that real capture needs the later genesis/admission workflow below; do not direct the user to capture into a pristine unbootstrapped Vault and pretend package can then run.

## 4. Profile preflight and optional parser

Provide separate `operator/parser_executor/pyproject.toml` and package `video_paper_wiki_parser_executor`, console `vpwiki-parser`. This package depends on this engine plus exact Docling 2.117.0/core 2.92.0 in its optional execution environment. It is not added to the root wheel/default lock and cannot dispatch vpwiki-admin. Production CLI never exposes a fake backend switch. Tests may inject a fixture converter via Python API only.

`vpwiki-parser profile --artifacts-path MODELS --session ID` reads an explicitly supplied local model tree, emits parser-config.json, model-manifest.json and sealed profile in `.work/research/<session>/manual-pdf/profile/`. No PDF run or model download. The tree must be a real directory; all entries regular files/directories, no symlink/special/hard-linked files or unsafe portable paths. Bound depth 16, ≤4096 files, per-file ≤4 GiB and aggregate ≤32 GiB. Hash files streaming with stable descriptor/stat checks; inventory sorted by relative UTF-8 path. Recheck complete tree membership/named identities and file content hashes before returning; adding/removing/changing a model fails, not a new profile under the same command. Empty tree is PARSER_MODELS_MISSING. This records actual supplied files; it does not certify they are the correct model set until conversion succeeds.

Parser config is exactly `{schema,engine,engine_version,core_version,options}`; schema `manual-pdf-parser-config.v1`, engine docling, versions pinned above; options exactly `{enable_remote_services:false,allow_external_plugins:false,do_ocr:false,do_table_structure:true,generate_page_images:false,generate_picture_images:false,do_code_enrichment:false,do_formula_enrichment:false,do_picture_classification:false,do_picture_description:false,do_chart_extraction:false,document_timeout:300,accelerator_device:"cpu",num_threads:4}`. CPU/4 threads is explicitly selected via the pinned AcceleratorOptions API. This is the initial digital-PDF profile, not an OCR guarantee. Local model path is runtime input and is not a semantic config/hash field. No options are silently inherited for remote/enrichment behavior. Unsupported pinned-runtime option/API is PARSER_RUNTIME_INCOMPATIBLE. Pinned API references: [converter](https://raw.githubusercontent.com/docling-project/docling/v2.117.0/docling/document_converter.py), [pipeline options](https://raw.githubusercontent.com/docling-project/docling/v2.117.0/docling/datamodel/pipeline_options.py); read-only API inspection is not a real runtime/model test.

Model manifest is exactly `{schema,files,total_bytes}`, schema `manual-pdf-model-manifest.v1`; files is sorted unique `{path,sha256,size_bytes}` for every regular file under supplied model root. Config and model JSON use engine JCS + LF. Profile data is exactly `{parser,parser_config,model_manifest}` where parser is the existing five-field Docling plan profile with config/model exact SHA-256, and parser_config/model_manifest are the exact closed objects just described. Fingerprint is derived from parser via existing identity API and returned, not an independently selectable value. Runtime versions are checked before profile creation using importlib.metadata; unavailable runtime is PARSER_RUNTIME_MISSING. No self-reported version substituted for installed metadata.

`vpwiki-parser export --intake INTAKE --profile PROFILE --artifacts-path MODELS --session ID --run-id ID` reads only the intake-bound `.work/blobs/<sha256>`, revalidates exact bytes/identity/PDF limits and retains/revalidates source/profile/model bytes throughout run and on failure. No Vault/captured-PDF flags, receipt audit or source-ledger prerequisites. Conversion receives retained exact PDF bytes through a local DocumentStream/BytesIO (not a URL or mutable filename); stream name is `<pdf_sha256>.pdf` for stable document naming. Use recorded config, explicit local artifacts_path, max_num_pages=300 and max_file_size=67108864. These are **staged model-produced artifacts**, not proof of capture/publication/accepted claims.

Force HF_HUB_OFFLINE, TRANSFORMERS_OFFLINE and telemetry-off in the dedicated process; disable remote services/external plugins and prevent Python INET socket creation/DNS/connect in this execution path. Restore patched process state on exit where API is used in tests. Offline flags alone are not claimed as OS sandbox proof; default agent runtime never imports this producer. No subprocess/network download fallback. Docling conversion must report SUCCESS, valid document export with at least one nonempty text item and page provenance consistent with the PDF, and preserve all exported text/table/picture/formula metadata. Empty/scanned-without-usable-text or partial conversion refuses with explicit capability/parse error; no pypdf output can masquerade as Docling. Full page count is processed within the 300-page/300-second requested parser limit; unsupported OCR/enrichment/picture pixels are clearly reported rather than guaranteed.

Emit exactly existing four roles under `.work/research/<session>/manual-pdf/runs/<run-id>/`: `document.json`, `parser-config.json`, `model-manifest.json`, `run.json`. `document.json` is deterministic stdlib JSON serialization of `document.export_to_dict()` using ensure_ascii=False, sort_keys=True, separators=(',',':'), allow_nan=False, plus LF; finite float coordinates are preserved. No invented Docling structure/version/source metadata. A complete export ≤64 MiB and JSON depth ≤64 is required. Config/model bytes are identical to preflight. `run.json` uses existing `video-paper-wiki.run-manifest.v1`, actual vpwiki/python/Docling/core versions, source/config/model exact input hashes, document exact output hash, actual started_at/ended_at, error_code null and existing pipeline_fingerprint. No receipt hash or plan hash cycle. Success stamps are never created on failure.

An already complete valid run-id directory returns the original exact run after revalidating its source/profile/model/document bindings without rerunning inference; a different input/profile for the run-id is a conflict. Incomplete prior run-id is explicitly incomplete/conflicting and requires a fresh run ID, never overwrite. For failed attempts keep one bounded `failure.json` in a distinct failed-run location with actual code/time/input refs when confinement allows; it is not a valid success run-manifest or canonical artifact. No automatic retry or timestamp rewriting.

Return the four confined paths/hashes/fingerprint, intake/profile refs, `state=staged_extraction`, `capture_authorized=false`, `receipt_backed=false`, `published=false`, and `next_action=source_analysis`. Do not create `video-paper-wiki.docling-artifact-set.v1` or use its captured_pdf_sha256 field in this staged lane. Context binds the four files/run/profile directly. The unchanged existing package function constructs the canonical artifact set only after later source admission. A compatibility test may independently supply an explicitly synthetic receipt-backed captured PDF to the existing package and prove these exact four bytes are accepted; that test is not an end-to-end source-admission observation.

## 5. Located source context and model proposal

`vpwiki-research pdf context --intake INTAKE --profile PROFILE --run RUN --upstream-root PIN --session ID` consumes the exact same-session four-file run directory, intake/blob and profile. Verify run source/config/model/document hashes and pipeline fingerprint against those bytes. No Vault or caller source-ID input. Derive `prospective_source_id` only through `verify_pinned_source_id` for the expected future `.raw/captured/<sha>.pdf` and exact digest; this authenticated read-only helper verifies the pinned formula, not that capture/ledger/receipt exists. This permitted helper is the only subprocess route involved. Canonical artifact paths and paper/source ownership are prospective. Do not use gold or manufacture authority.

Context data is exactly `{intake,profile,local_artifacts,run_sha256,paper_id,prospective_source_id,pdf_sha256,prospective_document_path,document_sha256,pipeline_fingerprint,evidence_scope,state,capture_authorized,receipt_backed,published,blocks,omitted,prompt_sha256}`. local_artifacts is a closed four-kind map to `{path,sha256,size_bytes}` for the retained same-session run files. Scope is `staged-pdf-text`; state is `staged_extraction`; capture_authorized/receipt_backed/published are all literal false. Paths/refs permit exact staged graph replay. Deterministically enumerate Docling `#/texts/N` nodes in document order, then provenance by page/span. Each block is `{block_id,text,locator}`; locator is the exact existing canonical wire string with prospective source/path, actual document/text hashes and derived geometry. `block_id = "mp1-block-" + SHA256(UTF8(locator_wire))`, covering every locator field including bbox rationals. `block.text` is exactly original node_text[start:end], never normalized or independently clipped.

Take whole eligible blocks in this order up to 128 blocks and 262144 total UTF-8 text bytes. At the first block that exceeds either budget, stop taking blocks and mark it and all remaining eligible text blocks omitted (`block_limit` wins when both limits are exceeded, otherwise `text_budget`). `omitted` is ordered `{ref,reason}`; reason is a closed enum `block_limit|text_budget|non_text_node|empty_text|unsupported_provenance`. A node with no supported provenance can be omitted with unsupported_provenance, but malformed/ambiguous purported supported provenance is an error, not silently omitted. Non-text tables/pictures/groups and empty text nodes receive their appropriate omission reason; refs can repeat for distinct omitted provenance blocks and retain traversal order. Bound combined exported node/provenance/omitted inventory to 20000; fail explicitly on excess. Every retained block receives truth validation. This basic text context preserves full table/picture/formula export separately and does not claim to understand all semantic content.

New `locator_truth.py` is mandatory, independent of existing shape-only validators. Frozen export profile: root `texts` is a list; each supported node is an object with scalar `text`, optional matching `self_ref="#/texts/N"`, and `prov` list. A provenance item uses `page_no` (exact integer, already 1-based), `charspan` (two exact integer code-point offsets) and `bbox` object with finite numeric `l,t,r,b` and uppercase `coord_origin=TOPLEFT|BOTTOMLEFT`. Root `pages` is an object keyed by canonical positive decimal page number strings; each selected page has matching integer `page_no` and `size:{width,height}` finite positive numbers. Extra native Docling fields are preserved but cannot supply aliases for these required fields; ambiguous/missing page keys, bool-as-int, surrogates, non-finite or alternate wire shapes fail.

Resolve only exact `#/texts/N` pointers (canonical index, no leading zero, alias or container). charspan is half-open `[start,end)`, `0 <= start < end <= len(text)`. Locator span equals one selected provenance span and text_sha256 hashes exactly its UTF-8 substring. Multiple disjoint spans produce distinct blocks; overlaps/ambiguous duplicate page/span coverage fail. Verify selected page geometry against retained PDF: this initial truth profile supports zero-origin, unrotated pages whose CropBox equals MediaBox; width/height must equal the PDF dimensions exactly. Unsupported rotated/cropped geometry is refused explicitly, not silently remapped. TOPLEFT bbox requires `0 <= l <= r <= width` and `0 <= t <= b <= height`; external order is `[l,t,r,b]`. BOTTOMLEFT requires `0 <= b <= t <= height`; external order is `[l,H-t,r,H-b]` using verified page height H. Convert finite numbers to exact integer ratios for arithmetic/comparison; require resulting coordinates to be exactly representable as finite JSON binary64 (otherwise refuse rather than round). Store through existing rational locator-wire encoding and compare exact ratios, never tolerance. Source/path/hash are checked against the staged context's prospective bindings. Omitted span/bbox is not accepted by this workflow. Test ref/text/span/page/bbox/source/path/hash/origin mutations independently.

Context tasks use shipped prompt bytes + LF + JCS of context data excluding prompt_sha256. No hidden platform prompt is claimed captured. The prompt asks the current model for the explicit transport-draft shape below and provisional claims. It does not ask the parser to invent claims or describe prospective source IDs as captured. Return exact task prompt/hash and context ref; CLI never invokes a model or assigns a known identity without evidence.

`vpwiki-research pdf analyze --context CONTEXT --proposal PROPOSAL --upstream-root PIN --session ID` validates unsealed `{context,generator,generated_at,prompt_sha256,transport_draft}`. Context is exact ref; generator exactly `{model,runtime}`, each `{value,identity_source,reason}` with platform_reported/self_reported/unknown; unknown requires literal unknown and nonempty reason, known requires nonempty value and reason null. Self-reports remain labeled. Verify complete staged context graph, prompt, prospective pinned source ID and locator truth.

`transport_draft` is a distinct closed object in the **new research proposal schema**: its fields and branches mirror existing paper-analysis-draft fields, with schema marker `video-paper-wiki-research.paper-analysis-transport.v1` and each claims[].locators[] containing canonical locator-wire strings. It is not valid as an old engine draft. Decode each wire to a locator object and replace only the schema marker with `video-paper-wiki.paper-analysis-draft.v1` to produce the legacy draft, then validate with the unchanged engine schema. Require same paper identity, ≥1 claim and ≥1 locator per claim, all assessments provisional, canonical claim IDs and locators drawn exactly from supplied blocks. Extra/altered locators, invented source/ref or accepted claims fail. All source fields remain prospective until later admission. Scientific support/language quality is not proven by these checks.

Sealed proposal data contains `{context,generator,generated_at,prompt_sha256,transport_draft,legacy_draft_sha256,state,capture_authorized,receipt_backed,published}`. State is `staged_analysis_proposal`, all three booleans false. Encode the projected legacy draft using the same finite-float JSON policy as document.json plus LF; hash its exact bytes into legacy_draft_sha256. Its path is derived solely as `proposals/<sealed-proposal-content_sha256>.draft.json`, so there is no self-reference cycle or caller-selected alias. Reuse/review must verify that companion file's hash and deterministic projection. No fabricated human assessment event.

Save immutable proposal/legacy JSON plus deterministic Markdown: title, literal staged/provisional status and PDF digest, existing section order, each claim in source array order with its exact text/ID and page/ref citations; no timestamps outside existing data, no model rewrite during rendering. It is review input, not a published/accepted paper. If no supportable claims exist, return SOURCE_ANALYSIS_EMPTY with retained context; do not force claims. Positive fixture demonstrates nonempty provisional claims and true locators. Source changes invalidate context/proposal; never relabel old bytes with a new hash.
